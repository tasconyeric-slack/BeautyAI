# 评测方案 v0.1（无需专家标注）

目的：证明系统**稳定、具体、有依据、守规矩**。不宣称准确性（那需要 v2 的顾问标注）。

## 数据

- 内部集 N = 8–12 人，每人 2 组照片（A、B，不同日期或不同光线），每组 front / smile / profile45。
- 每个人固定一份 `user_context`，两组照片共用，以隔离照片带来的差异。

## 指标

| # | 指标 | 计算 | v1 目标 |
|---|---|---|---|
| M1 | 跨照片稳定性（维度） | 每人 A、B 两组各维度差值的绝对值，取平均；量感与双极维度分开报告 | 双极维度 ≤ 0.5，量感 ≤ 0.6 |
| M2 | 跨照片稳定性（建议） | 前 5 条中前 3 条的类别集合 Jaccard 相似度 | ≥ 0.6 |
| M3 | 标签一致率 | A、B 两组风格主标签相同的比例；同时报告「属于对方前二」的比例 | 报告即可，临界样本单独列出 |
| M4 | 重复运行一致性 | 同一组输入跑 3 次：各维度标准差、前 5 条集合重合率 | 标准差 ≤ 0.3 |
| M5 | 评审分数 | D1–D5 平均分，pass / borderline / fail 分布 | D1、D2 ≥ 4；D5 = 5；pass + borderline ≥ 80% |
| M6 | 评审校准 | 人工给 10 份报告打 D1–D5，与评审模型的平均绝对差 | 报告即可；差异 > 1 的维度不作结论 |
| M7 | 效果图 | 「像本人」通过率、瑕疵率、降级率 | 通过率 ≥ 80% |
| M8 | 工程 | Schema 首次校验通过率、重试率、p50/p90 延迟、单份成本 | 首次通过 ≥ 90%；p50 < 60 秒 |

## 执行

```bash
python scripts/run_eval.py --data data/eval --runs 3 --judge   # 产出 eval/results.json
```

- `results.json` 是评测页唯一的数据来源，页面上不手写数字。
- 每次改 Prompt 或规则后重跑，把前后指标记进 `ITERATION_LOG.md`。

## 评测页结构

1. 顶部指标卡：M1、M2、M5、M7、M8 的关键数字。
2. 稳定性图：每人 A、B 两组在（量感，曲直）平面上的位置连线，线越短越稳定。
3. 评审分布：D1–D5 条形图，以及评审与人工的对比。
4. 案例：3 个成功案例、2 个失败案例（附失败原因与后续修正）。
5. 局限声明：评审模型衡量的是依据、具体性与合规，不等于建议正确；准确性需 v2 专家标注。
