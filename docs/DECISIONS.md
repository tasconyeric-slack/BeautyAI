# 决策日志（Decisions）

每条记录：决定、理由、放弃的方案、何时复议。复盘长文直接引用这里。

---

**D1 单一生产模型，另一个模型只做离线评审**（2026-09-29）
- 决定：线上只用一家模型做分析；另一家只在离线评测中担任评审。
- 理由：线上双模型投票会让延迟和成本翻倍，用户却感知不到。「模型评审」才是真实的 AI 产品开发方法，也能给出可展示的迭代证据。
- 放弃：GPT 与 Claude 在线投票取共识。
- 复议：若 W4 评测显示某类建议的跨照片稳定性长期低于 0.5，考虑只对该类做二次采样。

**D2 底层存连续维度，风格八型只是展示标签**（2026-09-29）
- 决定：模型输出量感、曲直、长短、软硬、成熟度五个连续维度；风格标签由规则层按最近原型推导，临界时标注「介于 A 与 B 之间」。
- 理由：风格八型是行业惯例，不是经过验证的分类体系。连续变量是真数据，标签只是界面语言，将来换体系也不会作废数据。
- 放弃：让模型直接输出风格类型。
- 由 D25 修订（2026-10-22）：八个标签对所有表达方向统一，不再按 presentation 换名。

**D3 v1 色彩诊断降级**（2026-09-29）
- 决定：只输出冷暖、深浅、对比三项；冷暖置信度上限 0.6，照片光线不一致时 0.4；色卡只作方向参考。
- 理由：手机照片白平衡不可控，12 季型属于伪精确。
- 复议：v2 引入白纸或色卡校准，加上顾问标注后再上 12 季型。

**D4 效果图只做局部蒙版编辑**（2026-09-29）
- 决定：从排名最高、且有编辑规格的建议生成效果图；只编辑蒙版区域，脸部内部永远不进蒙版；Prompt 由结构化字段确定性生成。
- 理由：一旦效果图不像本人，整份报告的可信度会一起崩掉。
- 放弃：整图重绘；让模型自由书写生图 Prompt。
- 由 D22 修订（2026-10-22）：生成式编辑仍只在发型 / 眼镜 / 领口蒙版内；确定性唇色、腮红、色调可进入妆容区域。

**D5 CV 用于质检与少量客观锚点**（2026-09-29）
- 决定：MediaPipe 负责质检门禁，以及长宽比、额颧颌相对宽度、中下庭比、眼距比这几项锚点；不算肤色 Lab、虹膜颜色、黄金比例。
- 理由：垃圾输入进不来，后面的结果才稳；更多的测量在普通手机照片上会变成伪精确。

**D6 不做颜值打分**（2026-09-29）
- 决定：产品中不出现任何颜值评分或排名；总体数字只有「置信度」。
- 理由：结果不稳定、有伦理风险，也和「开处方」的定位冲突。
- 由 D24 修订（2026-10-22）：本期只做“即将上线”预告（开关默认关），不建模型、不展示分数。
- 由 D36 取代（2026-10-23，Issue #31）：上线可解释的几何协调度参考分。

**D7 照片不持久化**（2026-09-29）
- 决定：照片处理完即删除，只保留 Passport JSON；效果图 24 小时后删除。
- 理由：人脸属于敏感个人信息；隐私优先本身就是作品亮点。

**D8 硬约束由规则层兜底**（2026-09-29）
- 决定：模型自报 `constraint_check`，规则层再用关键词守卫复核（含简单否定词识别），冲突时强制改判为违反约束并记 C5 标记。
- 理由：硬约束不能只靠模型自觉。
- 已知局限：关键词法可能误判复杂否定句；C5 标记方便人工复核。

**D9 用户自选「呈现方式」而非推断性别**（2026-09-29）
- 决定：`presentation`（feminine / masculine / androgynous）由用户选择，只决定建议领域（妆容还是理容）和标签用词。
- 理由：不推断敏感属性；男士形象建议通常做得敷衍，单独设计词表反而是差异点。

**D10 W1 生产模型：只用 DeepSeek，取消模型对比测试**（2026-09-29）
- 决定：W1 的三张照片分析只用 DeepSeek 多模态模型 `deepseek-flash`，通过其 OpenAI 兼容接口调用（沿用 `openai` Python SDK，但不使用任何 OpenAI 模型）。不实现 OpenAI 与 Anthropic provider，取消 GPT 与 Claude 对比测试（原 W1-T6），改为 5 人 DeepSeek 验收测试：输出质量、Schema 首次通过率、延迟、成本。
- 理由：先用一家模型把端到端管线跑通；Provider 接口保持最小（`analyze(images, system, user, schema, repair)`），以后接 Qwen / GLM 只需新增一个适配器。
- 放弃：W1 双厂商对比。
- 复议：若 W1-T6 验收未达标（首次通过率 < 4/5、D1/D2 抽查明显不足、p50 ≥ 60 秒），再引入 Qwen 或 GLM 做对比。验收结论补记在此条下。

**D11 图像编辑模型：Qwen 或 GLM**（2026-09-29）
- 决定：W2 的效果图在 Qwen 与 GLM 的图像编辑模型之间选择，由 W2-T3 对比测试决定。W1 不实现。
- 放弃：原计划的 GPT 图像模型 vs Gemini 图像模型。
- 待定：W2-T3 结论补记在此条下。

**D12 JSON 模式 + 本地完整校验 + 输出契约检查**（2026-09-29）
- 决定：DeepSeek 以 JSON 模式（`response_format = json_object`）返回，完整 `analysis.schema.json` 写进系统提示词。返回后先跑完整的 `validate_analysis()`，再跑 Schema 表达不了的输出契约检查（`check_output_contract`：建议 6–8 条、至少覆盖 3 个不同类别、观察与建议编号不重复）。任一失败，在同一对话中重发原始消息与图片、上一次输出和错误清单，重试一次；仍失败则明确报错。
- 不重试的情况：排序、约束改判（C5）、置信度上限（C6）、悬空证据剔除（C4）等规则层结果。它们由 `rules.py` 处理并记标记，不是模型输出违约。
- 理由：JSON 模式只保证可解析，不保证符合 Schema；规则层本身也不保证「至少 3 个类别」。
- 记录：每次 API 调用写入 `runs/<id>/calls.jsonl`（模型、输入与输出 token、延迟、停止原因、重试序号、估算成本）；Passport `meta` 只保留延迟、成本、重试次数的汇总，不改 Schema。

**D13 MVP 简报取代 PLAN.md 的流程**（2026-10-22）
- 决定：`docs/MVP_BRIEF.md` 取代 `docs/PLAN.md` 的周计划与全部 ⏸ 检查点，改为 S0–S6 纵向切片，每个切片提交一次、不停下等审批。5 人验收（W1-T6）、10 份报告通读（W1-T8）、Qwen 与 GLM 对比（W2-T3）、评审模型与评测页（W4）推迟到 MVP 之后。
- 保留的不变量：① 来源分层（CV → `input_quality`/`anchors`/`color_measurements`；模型 → `analysis`；规则 → `derived`）；② Schema 即契约；③ 单次请求只用一个生产分析模型；④ 阈值放配置；⑤ 范围红线（不打分、不给医美建议、不推断敏感属性）；⑥ 跨边界必校验、失败只重试一次；⑦ 照片不入库、按 TTL 删除；⑧ 密钥只走环境变量。
- 理由：作品需要先端到端可演示，再逐个模块加深；流程开销不产生用户价值。
- 分支：执行会话被分配到 `claude/aesthetic-passport-mvp-x94xoi`，它承担简报中 `mvp/v1` 的角色。

**D14 照片角色：正脸 + 45° 侧脸必填，微笑与发型照选填**（2026-10-22）
- 决定：`photo_id` 改为 `front`、`profile45`（必填）、`smile`、`hair`（选填，平时发型的侧面或背面）。质检门禁：`passed = front ≠ reject 且 profile45 ≠ reject`。
- 理由：三张必填的流失率更高；侧脸提供下颌与轮廓信息，比微笑照更有分析价值；发型照让发型建议有真实依据。
- 放弃：v0.1 的 front / smile / profile45 三张必填与 extra1 / extra2。
- 由 D20 修订（2026-10-22）：只需正脸；侧脸、微笑、发型照选填。

**D15 色彩：允许 CV 区域 Lab 取样作为输入信号**（2026-10-22，修订 D3 / D5）
- 决定：`color_sample.py` 在脸颊、眉、虹膜、唇、头发区域取中位数 Lab，写入 CV 层 `color_measurements`，只作为模型与规则的输入信号，不在界面上作为结论展示。置信度上限（C6）保留；新增 C12（模型冷暖与测量矛盾或测量可靠性低时再压低）。季型倾向只有通过门控规则时才展示，措辞永远是「色彩方向参考：偏向某季型」，绝不说「你是某季型」。
- 理由：手机照片无法校准，但区域测量能发现模型的明显矛盾，且对作品展示「测量 vs 模型」的分层很有价值。
- 复议：v2 引入白纸或色卡校准后，再考虑把测量值作为结论展示。

**D16 分析调用默认关闭思考模式**（2026-10-22）
- 决定：DeepSeek `deepseek-flash` 默认开启思考（effort high），且思考时忽略 `temperature`；JSON 模式与思考模式的兼容性官方文档未说明。分析调用默认 `thinking: disabled`（`config/models.yaml`），以 `extra_body={"thinking": {"type": "disabled"}}` 下发。S2 在同样的照片集上做开 / 关对比，记录首次通过率、延迟与成本，保留胜者。
- 待补：A/B 结果（需要 `DEEPSEEK_API_KEY` 与 `data/` 下的照片集）。

**D17 图像编辑：先用 Qwen `qwen-image-edit-plus`；像本人由蒙版回贴保证，不靠模型**（2026-10-22，暂定解决 D11）
- 决定：效果图调用阿里云百炼（DashScope 国际站）`qwen-image-edit-plus`。无论模型输出如何，最后一步都用「编辑区域蒙版 − 受保护面部区域」把结果羽化回贴到原图上，脸部像素永远是用户的原始像素。
- 理由：「不像本人」会让整份报告失去信任；把身份保护做成确定性的图像操作，比依赖模型自觉更可靠，也便于测试（受保护区域前后差异应为零）。
- 复议：若人工像本人检查不达标，再接入 Gemini 适配器对比。
- S5 补记（2026-10-22）：核对 Model Studio 文档——同一接口（`multimodal-generation/generation`，单轮、1–3 张图 + 1 段文字、可传 base64、同步返回 24 小时有效的结果链接）也服务较新的 qwen-image-2.0 系列，模型 id 放在配置里可直接切换；**接口不接受蒙版**，因此回贴是唯一的身份保护手段。实现：只把头部裁切图发给模型 → 去掉补边、缩放回原尺寸 → 编辑区域（原头发外扩 + 结果中新识别的头发）减去受保护区域（眉线以下的脸、眼、鼻、口）→ 羽化 11 px → 受保护区域 alpha 强制为 0。测试证明：即使假模型改动了每一个像素，受保护区域在编码前与原图逐像素相同。Prompt 升级 preview-0.2（不再说「蒙版区域」，因为模型看不到蒙版）；关闭 `prompt_extend`，固定 seed。
- 由 D22 修订（2026-10-22）：核心区（眼、鼻、口外扩）硬保护 + 边缘区（脸颊外缘、额角、下颌外缘）软保护 + 边界带颜色迁移；`seamless` 为 `qc.yaml` 配置开关。

**D18 报告顺序：先给答案**（2026-10-22）
- 决定：护照头卡 → 推荐造型 → 优先改进 Top 5 → 优势 / 拖后腿 → 发型 / 色彩 / 眼镜与修饰 / 照片呈现 → 视觉档案（我们怎么知道的）→ 局限与说明。
- 理由：用户先要结论和行动，证据与方法放在后面供想深究的人查看；「我们怎么知道的」是作品集展示架构的地方。

## V2（2026-10-22，Yeric 确认定稿；依据 `docs/v2/aesthetic-passport-v2.html` G1）

**D19 V2 交付方式**（2026-10-22）

**D20 输入：本地上传优先，只需正脸**（2026-10-22，修订 D14）
- 决定：`REQUIRED_ROLES = ("front",)`；侧脸、微笑、发型照选填。只用 `<input type=file>`，本期不做实时相机（无 `getUserMedia`）。

**D21 两段式分析**（2026-10-22）
- 决定：快速分析（`analyzer-quick-0.1`，≤1k token）与完整分析（`analyzer-0.3`）是同一生产模型的两次独立请求，各自校验 + 一次修复重试。结果以 `partial` 快照（anchors → quick → analysis → previews）经轮询返回，SSE 延后。快速分析失败不阻塞完整分析。

**D22 像素政策**（2026-10-22，修订 D4 / D17）
- 决定：生成式编辑只在发型、眼镜、领口区域；软保护回贴 + 边界颜色迁移；确定性唇色、腮红、色调可进入妆容区域，牙齿与眼睛永远排除，原图可逆对照。

**D23 分享卡**（2026-10-22）
- 决定：前端模板渲染 PNG；插画头像由参数生成、不描摹照片；所有卡片带显式“AI 生成”标识、隐式元数据（PNG tEXt `AIGC`）与产品署名。肖像模式每次单独勾选。

**D24 颜值评分**（2026-10-22，修订 D6）
- 决定：只做“即将上线”预告（`NEXT_PUBLIC_FEATURE_SCORE_TEASER`，默认关），只记录兴趣事件 `score_teaser_click`；生产构建禁止渲染任何分数，开发占位分只存在于 `web/lib/fixtures/dev_score_placeholder.json`。
- 由 D36 取代（2026-10-23）：预告卡与开关从产品页面移除，改为真实计算的“AI 面部美学参考分”。

**D25 风格：八个标签统一，四层分开**（2026-10-22，修订 D2）
- 决定：少女型、少年型、优雅型、浪漫型、自然型、古典型、戏剧型、前卫型（modern）对所有表达方向统一；四层（可观察特征 / 推断风格 / 个人偏好 / 目标形象）分开存储、分开展示；“不像我”只改偏好层与展示，不改写 ① 与 ②。

**D26 反馈**（2026-10-22）
- 决定：偏好与观察分离；反馈写入 `preference_events` 与 `user_context`，只经规则层重排（`derive(..., preference_events)`），不重跑视觉模型，不算重试；身形只来自用户输入。

**D27 商业**（2026-10-22）

**D28 照片质检：相对尺寸与原生清晰度**（2026-10-23，V2.1，修订 D14 的质检阈值）
- 问题：证件照式正脸被判“脸太小 / 模糊”。绝对 280 px 脸框阈值与“放大到 512 px 后的 Laplacian 方差”是主因。
- 决定：脸的大小按“脸高占画面比例 + 有效分辨率（脸框短边）”判断；清晰度只缩小不放大，在眼、眉、唇区域测 Tenengrad 梯度能量，不看脸颊。阈值在 `config/qc.yaml`。

**D36 AI 面部美学参考分**（2026-10-23，Issue #31；取代 D6 与 D24 的“不展示分数”，修订不变量 5）
- 背景：产品负责人把“分数 + 人群百分位”定为核心功能。竞品 The Face Report 公开了生产公式和大部分定义。
- 决定：
  - **公式**：总分 = 对称 35% + 三庭 25% + 五眼 25% + 长宽比 15%，每项 0–100。权重、三庭参考 18/41/41、长宽比参考 1.38 与“每 10 分约 5% 偏差”、对称的中线与特征权重、档位阈值 87/83/78/60 都来自公开页面。三庭换算常数由公开样例反推；对称与五眼的扣分常数是产品校准值。逐项出处见 `docs/scoring/COMPETITOR_FORMULA.md`，全部常数在 `config/scoring.yaml`。
  - **出处层级**：新增“打分层” `src/aesthetic_passport/scoring/`，复用 CV 层同一组正脸关键点和去倾斜坐标系（不跑第二个检测器），写入顶层 `aesthetic_score`。它是确定性计算，同一张照片、同一版本结果不变；模型不读也不写它，规则重排不改它。
  - **诚实状态**：`full`（四项齐全、照片条件好、可信度高）/ `limited`（已计算，但姿态、张嘴或笑、闭眼、眼镜或刘海遮额会降低可信度，绝不标为高可信度）/ `unavailable`（转头或俯仰过大、没有关键点、脸太小时，总分为空，不做估算）。
  - **措辞**：叫“AI 面部美学参考分”，说明它是几何协调度参考，不是整体外貌评价，也不是人群排名。档位用中性文字。改进方向只给发型、眉妆、拍照建议，不涉及医美。
  - **#41 接口**：`scoring.score_summary(passport["aesthetic_score"])` → `{overall_score, component_scores, scoring_version, quality_flags, status}`。百分位、参考分布与排名界面不在本决定内。
  - **免费**：分数与四项构成对所有用户可见，服务端不裁剪。
  - **界面**：档案页和首页（示例档案的分数由同一套打分代码在合成平均人脸上算出）展示分数主卡：四项构成、2 个相对突出项、1 个优先调整方向、进入测量工作台的入口。“即将上线”预告卡和 `NEXT_PUBLIC_FEATURE_SCORE_TEASER` 从产品页面移除。
- 局限：对称与五眼的扣分常数还没有在经同意的真实照片集上校准，只在 MediaPipe 的公开测试肖像上做过合理性检查。yaw 门槛比竞品宽（5° / 12° 对 2°），因为质检的 yaw 估计较粗。

**D37 参考人群位置与比例对照**（2026-10-23，Issue #41；在 D36 之上增加百分位，不修订其他决定）

  - **单一来源**：区域归属（117 项每项恰好属于一个区域）、对照公开评估分类的覆盖矩阵（已测量 / 文字观察 / 待研究 / 不做，并说明原因）、跨区域关系和按区间给出的造型提示都在 `config/face_atlas.yaml`，由 `make types` 导出到 `web/lib/generated/face-atlas.json`；`tests/test_face_atlas.py` 检查它与测量登记表、规则层和 analysis schema 一致，并检查文案不含禁用词。
  - **造型含义的优先顺序**：先用规则层对偏离常见范围项的建议，再用按服务端区间触发的提示（只在已测、可见、可信度不低时），然后是分析模型引用了本区域观察的建议和特点，最后才是常见范围内的建议。每条都写明依据并链接到对应建议页。
  - **诚实状态**：没有测量、模型也没有描述其形态的区域显示“这里不做猜测”；穿搭、眼镜、拍摄类观察只作为背景，不让区域算作“已观察”。侧脸区域只用真实侧脸照（未上传时显示补充入口）；耳部、睫毛、泛红、油光、毛孔等标为“不做”并说明原因。免费版被裁剪的数值不会出现在图谱中。
  - **证据图**：每个区域从它自己的照片裁出局部（正脸 / 侧脸），只画所选测量项自己的线；颈部只显示照片局部，不画线。悬停预览、点击固定沿用 V3B 工作台的交互；“工作台”按钮会切到对应照片并固定同一项。
- 放弃：在流水线里新增 `derived.facial_atlas` 字段（要改 schema 与规则版本，且只是重新分组已有内容）；让模型补写未观察区域的描述（会编造）。
- 局限：区间提示的文案基于示意范围，和 D35 一样尚未在真实照片集上校准；区域内容的丰富程度取决于分析模型这次描述了哪些部位。

**D41 真实流水线示例报告：AI 生成的虚构人物**（2026-10-24，Issue #14）
- 两位经产品负责人批准的 AI 合成成年虚构人物（person-001 / person-002），由 `scripts/build_demo_cases.py` 调用真实生产流水线生成：MediaPipe 质检 → 测量 → D36 几何参考分 → D37 参考人群位置 → DeepSeek 快速 + 完整分析 → 规则层 → `validate_passport`。脚本拒绝 `fake` 分析与 `QC_MODE=stub`，并逐张核对批准清单的 sha256。
- 输入角色：无眼镜正脸是唯一分析与测量来源；名义 90° 侧脸只有真实 QC 通过才进入侧面测量并发布；日常眼镜照仅为造型参考（D40），不测量、不送模型、不发布。
- 版本化快照放在 `examples/demo_cases/<person>/`（passport / geometry / provenance），网页导入逐字节相同的副本（测试保证）。provenance 记录输入与发布图片哈希、CV 引擎与模型文件哈希、评分与百分位版本、分析模型 / 提示词版本 / 重试 / 调用统计，以及“试看图未生成”“不含学习型外貌模型（#13 许可门槛）”。不依赖任何会过期的服务 URL。
- 发布图片：仅两人的正脸与通过 QC 的侧脸，同尺寸 RGB JPEG、去除元数据，原始 PNG 不改动；仓库默认忽略图片，这四张经人工审核后显式加入。这是不变量 7 的有限例外：只适用于批准的合成人物，绝不适用于用户照片。
- `/report/sample` 默认展示 person-001，提供两人切换与显眼的“AI 生成的虚构人物”说明；旧插画示例经 `?v=female|male` 保留。新增人物只需清单条目 + 运行脚本 + 一行导入。
- DeepSeek 新增 `DEEPSEEK_AUTH_VIA_PROXY=1`：凭据由出口代理注入时，SDK 发送占位密钥；`APP_ENV=production` 下忽略此开关，缺少 `DEEPSEEK_API_KEY` 仍然直接失败。
- 局限：两张合成肖像只证明流程可运行和身份一致的展示，不验证测量精度或人群分布；分析结果是一次真实调用的快照，重新运行会得到措辞不同的结果。


**D42 人类语义颜值参考分与排名 V1（2026-10-30；无需新增标注或采样）**
- 基于现有 `aes-geo-1.0` 几何参考分，采用**分位数对齐**而非除以 10 或任意指定线性系数：先假设该几何分与 TFR 已公布的扫描几何分布可近似对应，得到位置 p；再用 Hayden et al.（2007）1–10 分吸引力研究的中部组及 Top 5% 组均分拟合近似人类评分尺度 `H=4.955+1.062×Φ⁻¹(p)`。使用 Rhodes et al.（2011）的近似正态观察作为分布形状的额外假设。
- **这些都是V1产品假设，不是已证实的几何分与人工评分配对关系。** 结果显示为“AI颜值参考分（试行）”和“参考扫描估计排名”，不声称“真人对你的实际打分”或“真实全人群百分位”。
- 独立模块 `src/aesthetic_passport/percentiles/academic.py`，版本参数 `config/academic_rank.yaml`，完整出处和公式 `docs/scoring/ACADEMIC_RANK_V1.md`。沿用既有 Passport rank schema 和页面，不新增人工标注、面部数据集或模型推理成本。只用于 `full` 的 `aes-geo-1.0`，低质量/无效照片依旧不可用。
- 本决定仅对“该几何分在不做校准时不能显示任何位置”的 D37 规则开设**明确标注、可回滚的试行例外**；D37 的 TFR 校准闸门与学习型模型的匹配参考组闸门继续保持独立，不能把此估计伪装为验证后的排名。
