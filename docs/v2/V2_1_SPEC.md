> 状态：定稿，2026-10-23。适用分支 `v2`。
> 本文件修订 `docs/v2/aesthetic-passport-v2.html`（V2 PRD）与 `docs/v2/V2_TASKS.md` 中**与下文冲突的部分**；未提及的部分仍以 V2 PRD 为准。
> 决定记录：`docs/DECISIONS.md` D28–D33。

> 2026-10-31 导航修订（D44）：用户入口统一为「报告 / Studio」。原 A 档案、B 建议、D 行动合并为报告下的内容与工具；原 C 统一称 Studio。完成分析直接展示完整报告；已有详情路由保留。下文四区说明作为能力划分保留，不再作为一级导航。视觉统一使用报告的浅灰蓝主题，生产页面不随系统自动切换深色。

## 0. 为什么要改

V2 把很多能力做出来了，但它们像一组并列的模块：揭晓页过早给出数字与结论；发型页是三栏小卡和一张贴在页尾的大卡；每个页面都有自己的“看原图”与试看方式；试色、披布、发型试看分散在三个页面，无法组合。V2.1 只做一件事：**把这些能力组织成一条可信、可行动的顾问流程。**

用户要完成的四件事 → 产品的四个区域：

| 用户要做的事 | 区域 | 路由 |
|---|---|---|
| 了解自己的样子 | A. 我的形象档案 | `/p/[id]`（概要）· `/p/[id]/face` `/color` `/style` `/detail`（详情） |
| 找到适合的改进 | B. 个性化建议 | `/p/[id]/advice`（总览）· `/hair` `/makeup` `/outfit` `/glasses` |
| 预览并组合变化 | C. 形象实验室 Look Studio | `/p/[id]/studio` |
| 做决定并行动 | D. 我的行动方案 | `/p/[id]/plan` |

底部导航固定四项：**档案 · 建议 · 实验室 · 行动**（“我的”设置移到档案页右上角，穿搭检测仍在 `/check`，从建议页进入）。

## 1. 用户旅程

```
落地页 ─▶ 同意（2 项勾选）─▶ 一张正脸（≤300 ms 质检）─▶ 选表达方向（必填）
        ─▶ 两个可跳过的问题：最想改善什么 · 每天愿意打理多久
        ─▶ 分析中（真实阶段 + 面部测量动画，不出数字与结论）
        ─▶ 档案概要（一句话 + 脸 / 色彩 / 风格三卡 + “先做这一件”）
        ─▶ 建议（发型三方向等，文字为主，带“去实验室试”入口）
        ─▶ 实验室（发型 + 发色 + 唇色 + 近脸色组合到同一张照片，保存组合）
        ─▶ 行动方案（按优先级的 3 件事，可保存 / 勾选完成）
```

原则：先给价值，再问问题。上传前只问一个必答题（表达方向）；其余信息在“相关时”才问（例如进入发型建议时提示“烫染与留长条件”，在调整面板里随时可改）。

## 2. 输入

| 输入 | 必填 | 来源 | 说明 |
|---|---|---|---|
| 正脸照片 | 是 | 用户上传 | 唯一必需照片。质检见 §6 |
| 处理同意 + 年满 14 周岁 | 是 | 用户勾选 | 文案不变 |
| 表达方向 feminine / masculine / neutral | 是 | 用户选择 | **描述想要的造型方向**，不是对性别或身份的推断；随时可改 |
| 最想改善的方向 `goals[]` | 否 | 用户选择（最多 2 项） | 上传页可跳过；也可在调整面板里补 |
| 每天打理时间 `constraints.daily_minutes` | 否 | 用户选择 | 5 / 10 / 20 分钟 |
| 45° 侧脸、发型照 | 否 | “补充一点”页 | 只有新照片才触发模型重跑 |
| 发质、烫染、预算、场合、身形、风格偏好 | 否 | 调整面板 / 补充页 | 只影响规则层排序（D26） |

**可观察 vs 用户提供**：脸型、比例、五官特征、色彩倾向来自照片（并标注置信度）；发质、身形、预算、偏好、目标等照片无法可靠判断的内容只由用户提供，界面用“你告诉我们的”单独标出，不与观察混写。不推断年龄、种族、性别认同、健康、体重、体型。

## 3. 输出与区域

### A. 我的形象档案（免费核心）
- 概要页：一句话总结、三张档案卡（脸型与比例 / 色彩倾向与四季倾向 / 风格方向）、“像我 / 不太像”、置信度与局限一行、“先做这一件”。
- 详情（渐进展开）：面部页（三庭五眼、轮廓，测量数字只在这里出现）、色彩页（色卡、对比度、四季倾向）、风格页、详细分析页（观察条目 + 局限）。
- 每个结论分三层显示：**看到的**（观察 / 测量）→ **意味着**（解读）→ **所以建议**（跳到建议）。

### B. 个性化建议
- 总览页 `/advice`：按决策分组——发型与发色、妆容与理容、个人色彩、风格方向、眼镜与配饰、穿搭；每组一句结论 + 进入详情。
- 每条建议统一结构：**选什么 · 为什么 · 避免什么 · 需要什么（时间 / 花费 / 打理）· 怎么做**。
- 发型页：三张全宽纵向卡片（§5.1），文字建议免费；试看在实验室。
- 色彩页保留色卡与说明；数字披布移入实验室（色彩页留一个“在实验室里试近脸色”入口）。
- 妆容页保留方向说明与色板；试色移入实验室。

### C. 形象实验室 Look Studio（§4）

### D. 我的行动方案
- 默认只展示 **最优先的 3 件事**（按规则层排序 `derived.ranked_recommendations`），其余折叠。
- 每件事显示：优先级、能带来什么（expected_effect）、投入（effort 1–5 → 低 / 中 / 高）、花费（cost_band）、多久见效（time_to_effect）、怎么做（how_to）、怎么验证（success_check）。
- 可“加入我的方案”（保存）与“已完成”勾选；状态存本地（随护照删除）。
- 付费后额外显示按“今天 / 下次剪发 / 值得投入”分栏的完整计划（`derived.plan`）与实验室保存的组合。

## 4. 形象实验室 Look Studio

**一张主照片，下方（桌面为右侧）是图层控件；所有改动叠加到同一个造型。**

### 4.1 图层与渲染方式

| 图层 | 选项来源 | 渲染 | 费用 | 免费 / 付费 |
|---|---|---|---|---|
| 发型 | 三个推荐方向（稳妥 / 突破 / 省心）+ “保持现在” | Qwen 图像编辑，**需点“生成这个造型”** | 每次 1 张 | 付费 |
| 发色 | `hair_color_directions`（≤3）+ “保持现有发色” | 与发型**合并为同一次** Qwen 请求 | 同上 | 付费 |
| 唇色 | `lip_families`；表达方向为 masculine 时默认隐藏 | 本地 `lipTint`，即时 | 0 | 免费（免费版色板为前 2 个） |
| 腮红 | `makeup_direction.blush` | 本地 `blush`，即时 | 0 | 免费 |
| 近脸色（披布） | 近脸色 + 衣橱底色 + 慎用色 | 本地 `drape`，即时 | 0 | 免费 |

- **身份参照永远是原始正脸**：每次发型生成都从原图出发（服务端 `front.jpg`），不在生成图上再生成，避免累积失真。
- **合成顺序**：底图 = 原图；若当前发型 + 发色组合已生成，把生成图按其裁切框贴回原图位置（生成图在保护区外与原图逐像素一致，在面部核心区逐像素就是原图）；再依次叠加近脸色 → 腮红 → 唇色（几何来自 `/geometry`，与原图同坐标）。因此本地图层在生成图上同样准确。
- 发型或发色改变后，若该组合尚未生成，主图显示原发型（其他颜色图层照常叠加），并提示“发型尚未生成，照片上仍是现在的发型”，主按钮为“生成这个造型”。不自动生成，避免把一个发型的结果误当成另一个。
- 生成状态：空闲 → 生成中（约 20 秒，可继续调颜色）→ 成功（标注“AI 试看”）/ 失败（显示原因 + “重试”，保留其他图层）。照片过期（24 小时）后实验室只显示色卡与文字，并说明原因。
- **唯一的对比控件**：主图下方“按住看原图”（指针 / 触摸 / 空格或回车键均可）。
- **诚实标注**：发型与发色是“AI 近似模拟”，实际效果取决于发质、剪裁与染发；唇色、腮红、近脸色是“基于当前照片光线的颜色模拟”。
- **保存组合**：“保存这个造型”把 {发型, 发色, 唇色, 腮红, 近脸色} 存为一个命名组合（本地，随护照删除）；保存时若含推荐发型，同时记一条 `hair_option` 的“喜欢”反馈，用于后续排序（D26）。行动方案页显示已保存的组合。
- 入口与预选：`/p/[id]/studio?hair=bold&lip=%23B5707A&drape=%231F4E5F`；发型卡的“试试这个发型”、色彩页、妆容页都带参数跳入。

### 4.2 API 变化（不重写后端）
- `POST /api/passport/{id}/previews` 的 `target_ids` 支持组合 id：`<发型>` 或 `<发型>_hc<i>`，发型取 `safe | bold | easy | current`（`current` = 保持现在的发型，只改发色，必须带 `_hc<i>`）；`i` 是 `hair_color_directions` 的下标。服务端把发色写进同一个编辑描述。
- `partial.previews[]` 增加 `crop_box`（归一化 `[x0, y0, x1, y1]`，相对原图），供前端把生成图贴回原图。
- 不在任何日志中记录照片或其派生数据；生成图与原图同寿命（24 小时）。

## 5. 交互规范

### 5.1 发型推荐卡
- 三张**全宽、纵向堆叠**的卡片（手机与桌面相同，桌面最大宽度约 720 px）。
- 卡片内容顺序：方向标签 + 名称 → 为什么适合你（来自该方向引用的观察）→ 参数（长度 / 刘海 / 卷度 / 发色 / 体积，两列短表）→ 打理与代价（每天分钟数、修剪周期、需要烫 / 染 / 留长、与条件冲突的提醒）→ 保留 / 改变 / 避免 → 操作。
- 操作：主按钮“就选这个”；次按钮“试试这个发型”（进入实验室，预选该方向）；反馈“喜欢 / 还可以 / 不喜欢”。
- 卡片不嵌入图像编辑器；若已有该方向的 AI 试看，只显示一张小缩略图，点击进入实验室。

### 5.2 反馈
- “不喜欢”后在卡片内展开一块全宽区域（手机上为底部弹层），原因标签按词自然换行；标签不允许逐字断行（`word-break: keep-all` + `white-space: nowrap`）。
- 原因选完自动提交，显示一行“已记下，会少推荐类似方向”。

### 5.3 选定发型 → 发型师简报
- “就选这个”打开底部弹层（桌面为居中弹窗）：发型名称、三句可以直接对发型师说的话、要避免的、打理要求。
- 操作：“复制给发型师”（复制纯文本）、“保存到我的方案”（记“喜欢”反馈并加入行动方案）、次要入口“导出沟通卡图片”（原 StylistCard，移到分享页）。
- 弹层可用 Esc / 点遮罩 / 关闭按钮关闭，打开时焦点进入弹层。

### 5.4 原图对比（全站统一）
- 默认显示处理后的图，**只有一个“按住看原图”控件**；删除“原图 / 拖动对比 / 试看图”三段切换与拖动滑块。
- 指针按下 / 抬起、触摸、键盘空格或回车按住都有效；失焦或指针取消时恢复。
- 数字披布、唇色等本地图层同样只用这一个控件。

### 5.5 分析中页面
- 保留：用户原照片、面部关键点与测量线动画、真实的后端阶段。
- 删除：所有测量数字、快速结论、特征标签、风格 / 脸型结论。
- 阶段文案与后端状态一一对应（不加假进度、不加人工审核暗示）：

| 后端状态 | 文案 |
|---|---|
| 还没有 anchors | 正在建立你的面部特征档案 |
| anchors 已到（`stage = quick`） | 正在识别面部关键区域 |
| quick 已到（`stage = analysis`） | 正在整理轮廓与比例信息 |
| analysis 完成、正在组装 / 规则（`status = full_ready` 前最后一步） | 正在生成个性化形象建议 |
| `analysis_failed` | 分析暂时中断（保留“重试一次”） |

- 只有 `full_ready` 才显示档案。

## 6. 照片质检（修订 V2 的 280 px 与 Laplacian 阈值）

问题：证件照式正脸（脸占画面高度一半以上，但整图只有约 400–600 px 高）被判为“脸太小”和“模糊”。原因：
1. 脸框以绝对像素（短边 < 280 px）判断，与脸在画面中的占比无关；
2. 清晰度在“缩放到 512 px 的脸部裁剪”上算 Laplacian 方差——小图被**放大**后高频被插值抹平，清晰的小照片也被判模糊；光滑皮肤、JPEG 压缩与缩放进一步压低该值。

修订（阈值在 `config/qc.yaml`）：
- **脸的大小 = 相对占比 + 有效分辨率**。`face_too_small` 只在“脸高占画面高度 < 20%（且脸宽占画面宽度 < 18%）”或“脸框短边 < 120 px（有效分辨率不足以测量）”时警告；拒绝只在短边 < 80 px。证件照（占比 > 40%、短边 ≥ 180 px）不警告。
- **清晰度 = 原生分辨率上的五官细节**。只缩小不放大（脸宽统一缩到 ≤ 256 px，小于此宽度保持原样）；在眼、眉、唇三个有纹理的区域测梯度能量（Tenengrad 中位数），不看脸颊（光滑皮肤本来就没有纹理）。用“五官 / 脸颊”的对比与绝对梯度共同判断：只有五官边缘也明显变软时才判模糊。
- 前端同样不再显示“脸偏小”这类基于绝对像素的提示；质检结果仍只给一条重拍建议，且只在有拒绝或可信警告时出现。

## 7. 免费 vs 付费（一次性购买，D27 不变）

| | 免费 | 完整护照（一次性） |
|---|---|---|
| 档案 | 脸型、比例与特征概要、四季倾向、风格方向、置信度 | 详细测量解读与详细分析页 |
| 发型 | 三个方向的**文字**建议（参数、打理、保留 / 改变 / 避免、发型师简报） | AI 发型试看 |
| 色彩 / 妆容 | 色卡、2 个唇色、腮红与近脸色本地试色 | 全部唇色 |
| 实验室 | 本地颜色图层（唇色 2 个、腮红、近脸色） | 发型 + 发色 AI 生成与组合造型 |
| 穿搭 | 2 条公式、4 件单品 | 全部公式、单品与场合方案 |
| 行动方案 | 最优先 3 件事 | 三栏完整计划、眼镜 mm 尺寸 |

- 免费不再自动生成“稳妥”试看（`free_previews: 0`）：照片级发型试看只属于付费。
- 邀请码解锁保留（测试 / 内测用）。
- 权益仍由服务端裁剪响应，前端不靠隐藏来“锁”。

## 8. 隐私
- 24 小时照片删除策略不变：原图、缩略图、生成图、geometry 同寿命；裁切框随生成图一起过期。
- 实验室的本地图层完全在浏览器内计算，不上传任何像素；保存的组合只存颜色值与选项 id。

## 9. 验收

- 清晰的证件照式正脸不被判为“太小”或“模糊”；真正模糊、过小、多人、无人脸仍被拒或警告（测试覆盖）。
- 分析中页面有测量动画、无任何数字或结论。
- 三张发型卡在 375 px 与桌面宽度下都纵向排列；“不喜欢”原因标签可读、自然换行。
- “就选这个”打开简报弹层，可复制给发型师、可保存。
- 全站原图对比只有一个“按住看原图”控件。
- 实验室能把发型、唇色、近脸色组合成一张预览并保存。
- 免费用户能看到三个方向的文字建议，不能生成照片级发型试看；付费 / 邀请码用户可以。
- 上传 → 分析 → 档案 → 建议 → 实验室 → 行动方案全程可走通（假模型 e2e）。
