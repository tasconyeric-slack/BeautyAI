# R3 验收与 R3.1 体验修订

2026-10-29。依据负责人对 Claude R3 的反馈：目标是成体系的整站视觉和自然动态交互，不能将素材齐全、页面可点、截图和 Figma 导入等同于设计完成。

## 验收结论

R3 作为素材与组件状态底稿可复用，尚不能作为最终设计通过。实际运行了所交付 `home.html`，查看了首页、测量解读、Studio 源码与画面：

| 方面 | R3 实际情况 | 本轮修订 |
| --- | --- | --- |
| 整体设计 | 沿用了纸色、灰色、绿色和衬线标题，但八段多数是同一种标题加介绍、照片加说明结构 | 首页形成开场、阅读、人物摄影、造型探索、深色 Studio、报告实物的连续节奏；共用导航与文字层级 |
| 滚动交互 | 测量切换、照片聚焦和方案主要由点击触发；普通滚动不展开这些内容 | 连续阅读三段真实解读，照片固定在阅读位置，随滚动改变聚焦和测量线，进度同步 |
| 页面内动画 | Hero 已有自动过程，后续主要是按钮反馈与淡入 | 发型对比进入视口后自动揭示一次；Studio 自动介绍选择与比较，随后等待用户操作；摄影随进入画面轻微移动 |
| 发型内容 | 同一人物在发型、Studio、报告中重复占用大量画面 | 首页只突出一组原图与发型对比，更多方向放进 Studio，不做多人物多发型墙 |
| 眼镜 | 默认 Studio 场景同时加了发型、唇色、眼镜，贴合效果不足 | 六位人物展示均使用无附加眼镜原图；Studio 默认原图，无眼镜；选镜收为按需入口，本轮不再把贴合不足的镜框叠上脸 |
| 报告 | R2 内容和组件已有明确方向 | 直接复用现有 `SampleReport`，不重画或改写已有报告 |

当前打开的 `/dev/style-showcase` 属于 PR55 的素材展示试验，并非 Claude R3 的完整首页/Studio，也不能代表本轮整站成果。

## 直接观看

- `/dev/design-motion`：保留实际 Hero，接续新的连续首页。
- `/dev/design-motion?view=report`：同一导航下查看实际 R2 完整报告。
- `/dev/design-motion?view=studio`：同一视觉语言下的 Studio 代表性交互。

只在开发或 Vercel preview 环境开放。此轮是可操作的设计体验稿；生成质量修复、个人 Studio 的工程替换、上传/QC与行动计划的全页铺开尚未交付。

## 统一设计语言

采用已认可方向：暖纸色为阅读底，照片原背景灰为测量舞台，苔绿色为选中与解读重点，深灰为 Studio 的集中工作区。标题用现有中文衬线字体，正文和操作用无衬线，测量读数用等宽字体。每屏由一个主要视觉带动，辅助内容不与人物抢占面积。

同一套线条、字号层级、留白、圆角按钮和选中反馈贯穿首页、报告入口与 Studio。报告内容仍由 R2 自身样式控制；Hero 直接使用原组件，其样式与动画不重写。

## 动态语言

| 动态 | 用途 | 行为 |
| --- | --- | --- |
| 滚动带动阅读 | 从结构到重心再到配色 | 原生滚动，照片 sticky；切换时取景 1250ms，真实测量线随后绘出；正文一直可读 |
| 照片进入画面 | 人物摄影保持轻微生命感 | 各人物错开出现；支持的浏览器使用原生 view timeline 轻微位移 |
| 自动比较 | 无需点按钮也能看到发型差异 | 进入画面后 6.5s 揭示原图、模拟图并停在中间；拖动或键盘接管后停止自动过程 |
| Studio 自动介绍 | 让选择与比较关系自然显现 | 进入视口后每 3.3s 展开一步，最多两步；不自动替用户保存；用户开始操作即接管 |
| 状态切换 | 选方向、按住原图、配色、保存 | 原位交叉淡化、选中线条、保存确认；配色只改变照片周围配色，明确保留照片原色 |
| 减少动态 | 同一内容的静态呈现 | 跟随系统：停止自动演示与位移；滑动阅读、选择与比较仍可操作 |

滚动和定时自动演示分工不同：滚动展开内容，自动过程介绍一处组件。没有强制翻页、拦截滚轮或必须逐项点开的演示流程。视口外、隐藏标签页暂停自动介绍。右下角预览工具可随时暂停；Hero 的原有播放控件保留。

## 参考与实现选择

参考 [QOVES](https://www.qoves.com/) 的摄影主导、连续内容和动态体验目标；只取本项目适用的表现方向，不复用其素材、代码和价值承诺。

比较：原生 CSS / IntersectionObserver（本轮采用，无新依赖）；GSAP（复杂长时间轴时再评估）；Motion（现有栈未使用，为本次两处演示引入并不必要）。取景复用已有 `camera`、`focusBox`、`MetricLines`；报告复用 `SampleReport`；按住原图复用 `HoldButton`。

原生参考：[CSS animation-timeline](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-timeline)、[IntersectionObserver](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)。

## 2026-10-29 正式页面接入

在认可提交 29a971f 基础上，正式 `/` 复用相同连续首页。导航和解读入口进入 `/report/sample?v=p002`；个人 Studio 入口进入 `/start`，不经过受环境限制的 `/dev`。首页仍明确使用 AD3611 的 AI 模拟图，删除生产首页演示内假保存按钮，改为上传个人照片入口。

真实 `/p/[id]/studio` 使用灰色照片舞台、深色控件区、苔绿选择线。继续复用现有生成请求、状态轮询、裁切合成、按住原图及设备选项保存；没有自动调用生成，也不自动替用户保存。保存后核验 localStorage 写入，失败时不宣称完成、不选择发型。真实 UI 只有 succeeded 结果实际载入后才称已叠加；保存的是选项，图像仍按原期限删除。

上传指南进入视口后有限介绍光线与正脸要求，离屏/隐藏暂停，触摸或键盘接管后停止，减少动态时静止。等待页仅使用真实后端阶段和匹配 geometry：没有 geometry 时只显示轻微边框呼吸；取消原来用唇眉距离估算的鼻底横线，只用真实 subnasale（老 geometry 无此点则不画）。行动计划使用真实已保存选项数量作为 Studio 回访入口。
