## 3. 技术核验（元数据层）

### 3.1 已发布母版的尺寸事实（更正版）

四张已发布母版共出现 **三种尺寸**；**同一人的正/侧是否同尺寸并不一致**：

| 文件 | 宽×高 | 宽高比 |
|---|---|---|
| `person-001/front.jpg` | 1088×1456 | 0.747 |
| `person-001/profile90.jpg` | 1088×1456 | 0.747 |
| `person-002/front.jpg` | 1122×1402 | 0.800 |
| `person-002/profile90.jpg` | 1024×1536 | 0.667 |

**准确表述**：
- P001 正/侧**尺寸完全相同**（1088×1456），可共用同一组裁切参数。
- P002 正/侧**尺寸不同**（1122×1402 与 1024×1536）。
- 上表数值与 `provenance.json` 的 `published_images` 字段逐项一致，可交叉验证。

**不可由此推出**：尺寸差异是**发布阶段各自裁切的结果**，不构成机位、对齐、身份或画面内容差异的证据。正侧并置时需分别定义裁切参数，属工程事实；是否形成视觉问题需由视觉评审判断，**不在本次审计结论内**。

### 3.2 展示裁切与母版的比例差异

展示 WebP 统一 960×1200（0.800）；P001 母版为 0.747。同一人在 Hero 使用编辑图、在报告使用母版时，两者的容器留白比例不同。**由此产生的实际观感差异未经视觉验证**，仅提示设计侧不要假定额定同一裁切框。

### 3.3 声明性元数据（非画面判断）

- **朝向**：`portraits.ts` 声明 P001 侧脸 `facing:"right"`，P002–P006 为 `facing:"left"`。此为元数据声明，本次未核对画面；左右分栏版式若不做分组，视线方向会不一致，且**不可翻转图片**来凑版式。
- **身份配对**：六人全部 `identityPairVerified:false`。任何「同一人正面与侧面」的并置说明，都不得暗示生物特征配对已成立。
- **未公开配镜参考**：P001/P002 的 `provenance.json` 记有 `glasses.png`，用途为 styling reference only（不测量、不进模型、不发布），存于 git-ignored 母版目录。**它不是可用配镜资产，也不能从仓库取得。**
- **体积**：12 张 WebP 合计约 1.19 MB，单张 68–144 KB，属元数据层可确认的范围，适合懒加载。

## 4. 「仓库内缺失」与「未通过验收」的区分

这是本次审计最容易误判之处：**`V3_ASSET_PLAN.md` §4 规定「no image bytes pushed to Git before approvals」，且母版存放于 git-ignored 的 `data/demo-assets`（`provenance.json` 的 `local_dir` 字段）。因此「仓库里没有」是候选资产的正常状态，而非「从未生产」。**

| 资产 | 仓库内 | 可能的本地状态 | 生产验收 | 正确结论 |
|---|---|---|---|---|
| P0-A P001 编辑级母版 | 确认无文件 | 无法判定（可能已有候选） | 无记录 | 未通过验收，不可用于生产 |
| P0-B P001 发型前后对比 ×2 | 确认无文件 | 无法判定 | 无记录；身份稳定性亦未验证 | 未通过验收，不可用于生产 |
| P0-C P002 镜框形状 ×2 | 确认无文件 | 无法判定 | 无记录；权利与贴合未决 | 未通过验收，且权利未建立 |
| P1（P004/P006 变体、局部特写） | 确认无文件 | 无法判定 | 无记录 | 未通过验收 |
| P2（P003/P005 造型） | 确认无文件 | 无法判定 | 无记录 | 未通过验收 |
| `editorial/`、`eyewear/`、`crops/`、`before-after/` 目录 | 确认无此目录 | 无法判定 | — | 仓库内无对应交付物 |

> 结论应表述为：**「没有任何编辑级、前后对比、配镜或局部特写资产通过生产验收并提交入库」**，而不是「从未生成」。后者超出仓库可证明的范围。
