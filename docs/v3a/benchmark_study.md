# 颜问公开面部美学体系研究与 BeautyAI 评测引擎升级规格

**研究日期：2026-10-23**  
**项目：** BeautyAI-Assessment-System，目标分支 `v2`，当前 V2.1 规格与 schema `0.3.1`  
**定位：** 公开功能对标 + 独立设计复现。不声称恢复颜问的私有算法、全部真实内部指标、数据库或原创界面资源。

## 0. 执行摘要

颜问的核心能力不是一张“颜值分数卡”，而是：面部关键点/轮廓检测 → 可解释的几何与外观指标 → 四大评估支柱 → 叠在用户照片上的测量图 → 指标分层解读 → 改善方向与顾问服务。BeautyAI 应把这套“可测、可解释、可行动”的方法融入现有 **档案 / 建议 / 实验室 / 行动** 四区，不推翻当前 V2.1。

### 确认度

- **事实确认**：颜问网站公开展示四支柱、100+ 指标的产品宣称、16 个有名称或展示代码的指标、面部标注/报告示意、部分打分/百分位展示、评估范围和流程。来源见文末。
- **推断/独立建议**：176 项候选目录、测量公式、阈值、权重、可视化细节、我们的数据结构与实现工期，均为我们独立构建，不是颜问内部实装的等同复制。
- **无法核验**：颜问其余未公开的指标名单、S/F 全序列、阈值、非线性评分权重、训练集、真实准确率、完整登录后报告、收费和账户页面、后端技术栈、三维模型是否为真实重建。

## 1. 颜问在公开资料中确认的测评结构

### 四大支柱（当前首页）

1. **和谐度 Harmony**：面部区域之间的大小、位置、方向、比例和协同；不是“必须三庭相等、五眼相等”。
2. **头脸架构 Head-Face Architecture**：额、颞、颧、颌、颏的宽度及过渡，轮廓变化和三维外观。
3. **二态性 Dimorphism**：面部特征的男性化/女性化视觉连续谱，不等同于用户性别或认同；官网称其不是越极端越好。
4. **皮相细节 Skin Detail**：肤色均匀度、纹理、毛发、眼唇等局部细节。

早期 `/team` 索引展示过“和谐度、轮廓清晰度、二态性、皮相细节”的另一种分法。对标以最新首页的四支柱为主；另设跨支柱展示类 `contour_clarity`。四大支柱不强行要求每个指标互斥，因为“眼角倾斜度”也可能同时贡献和谐感与表现力。

### 对外展示/用户报告模块

- 综合美学评分和示例百分位；正脸和谐度、侧脸、皮相、轮廓清晰度、对称性等单项分数；
- 面部三庭比例；眼眉、虹膜色彩、二态性、对称性、面部比例等分析块；
- 正面面部测量图、侧面角度线、单项指标叠加展示；
- 当前状态和医美/非医美潜力的人群位置可视化；
- AI顾问与发型、妆容、穿搭改善建议。

上述是公开文案和演示，**不保证免费/正式用户实际能看到全部项目**。百分位真实性、性别×族裔分群准确率和所有训练数据都不可独立核验。

## 2. 我们的独立完整候选测量目录

见附件：
- `facial_metric_catalog_v1.csv`（Excel 可直接打开、含 UTF-8 BOM）；
- `facial_metric_catalog_v1.json`（可供开发导入）；

**共 176 项候选指标**，其中：
- `A`：58 项，存在基础 2D 几何计算路径，仍需质检、锚点定义与姿态校正；
- `B`：98 项，依赖高质量分割、特定照片角度、光照校准或模型扩展；
- `C`：20 项，仅能做定性观测或当前缺乏可信的单照片测量方法，不允许伪装成精密分数。

分组及数量：整体面型与宽高 16；纵向比例与五等分 16；眼部 18；眉与眉眼关系 11；正面鼻部 14；唇与口周 14；轮廓颌颏 13；左右对称 14；侧面投影 20；皮相 14；毛发造型 10；综合及决策 16。

**这 176 项是开发候选池，不能意味着 176 项现在已能准确测量、176 项来自颜问，或每项都应出现在免费报告。** 其中存在关联/派生/互补指标，不能把数量视为模型独立信息量。

## 3. 面部图像分析的工程边界

### 正脸照片能做

- 可靠的 2D 关键点坐标、角度、相对比例、部分面积和镜像不对称测量；
- 在良好分辨率、无遮挡条件下测量眼唇曲线、鼻翼宽度、外轮廓宽度；
- 适度观察当前照片中的肤色与纹理，但需告知光照/美颜影响；
- 生成脸上叠加的参考线、多点标注、局部放大和指标说明。

### 必须要侧脸或严格附加条件

- E-line、鼻唇角、鼻额角、颏唇角、鼻尖/下颏相对突出度，以及其他侧面轮廓投影；
- 额、颧、颌的真实立体深度、真实“折叠度”、深宽比及骨量 **不能由普通单张 2D 自拍可靠还原**；
- 绝对毫米距离需已知尺标/相机参数/经过验证的深度估计；仅凭像素除以平均虹膜直径得到的毫米只能作为粗略估计；
- 微小毛孔、细纹、皮肤弹性和临床皮肤情况不可凭普通前置相机可靠量化。

### 分数与百分位

目前 BeautyAI `CLAUDE.md` 与 `docs/DECISIONS.md` D24 明确：生产环境不展示颜值评分或排名（只可 teaser）。本任务默认 **优先上线客观测量 + 特征档案 + 改善建议**，不直接修改该决策。

若以后决定做“面部吸引力评分”，必须独立明确：
1. 评分的目标是什么（真人审美的某种统计汇总？偏好条件？），且不能称其为客观事实；
2. 经授权、知情同意的真人多评分者数据；
3. 训练/验证分离、年龄/光照/设备/表达条件评估及模型不确定度；
4. 同一用户照片跨光照/姿态稳定性与群体误差分析；
5. 百分位仅在样本来源/分布具有代表性时显示，禁止用正态曲线凭空推算。

**不能复刻颜问示例数值、宣称其样本量归自己所有，也不能编造第 x 百分位。**

## 4. 与 BeautyAI V2.1 的代码对接（已核对 v2 分支）

### 保留现有约束

- `CLAUDE.md`：CV 负责 `anchors`/几何，LLM 负责 `analysis`，确定性规则负责 `derived`；保持边界。
- `docs/v2/V2_1_SPEC.md`：档案/建议/实验室/行动四区；正脸必填、侧脸选填；24 小时照片/几何删除；一次性付费；免费的基础档案。
- `anchors.py`：现有 5 个核心 anchor（脸长宽、额/颧/颌宽、下庭/中庭、眼间距/眼宽），以及额外三庭、五等分和 iris px/颧宽 px 等；均可复用。
- `anchors.export_geometry`：已有眼、眉、唇、脸轮廓与颈部 polygon，但尚非完整的鼻、面颊、侧面测量标志点集合。
- `schema/passport.schema.json`：`additionalProperties:false`，应明确升级 schema，而不是悄悄插字段。`0.3.1` 是当前已核验版本。
- 现有项目不根据照片推断性别认同、年龄、族裔、体重或健康。表达方向 feminine / masculine / neutral 是用户选择的**造型偏好**，不是生物属性测定。

### 建议引擎结构

```text
front image / optional profile
     ↓
photo QC & pose normalization (existing)
     ↓
MediaPipe landmarks + additional optional segmentation
     ↓
landmark adapters & regional masks
     ↓
face_metrics/               # NEW, numeric measurements in CV provenance
  registry.yaml             # id, name, camera view, formula, dependency, reliability
  geometry.py               # distances, ratios, angles, curves
  frontal.py                # front metrics
  symmetry.py               # left-right residuals
  profile.py                # optional side metrics
  appearance.py             # conditional color/texture observations
  availability.py           # missing/occluded, source, confidence
     ↓
measurement_profile        # NEW in passport (new schema version)
     ├─ metrics[] {id, value, unit, confidence, evidence, applicability, missing_reason}
     └─ sources {front, side, method, capture conditions}
     ↓
analysis (LLM)             # describes only supported observations, no fabricated numbers
     ↓
derived (rules)           # determines actionable advice priorities, not aesthetic 'truth'
     ↓
web /p/[id]/face           # interactive visual assessment
web /p/[id]/advice         # explain metric → recommendation links
web /p/[id]/studio         # preview only (not a geometry measurement tool)
```

### 面向后端的最低契约

```json
{
  "metric_id": "M033",
  "name_zh": "一目间隔测试",
  "value": 0.97,
  "unit": "ratio",
  "availability": "measured",
  "method": "frontal_2d_landmarks_v1",
  "source_photo": "front",
  "confidence": "high",
  "points": ["left_inner_canthus", "right_inner_canthus", "left_outer_canthus", "right_outer_canthus"],
  "overlay": {"type": "segments", "ids": ["intercanthal", "eye_width_l", "eye_width_r"]},
  "interpretation_scope": "descriptive_only"
}
```

`value` 为示意数据，不是任何真人/颜问的真实测量。缺失时 `value:null`，配 `missing_reason`，不得以模型猜测补数字。

### UI 具体要求

面部页面改成由浅入深的 4 层：

1. **第一屏结构画像**：原照片的清晰测量标注 + 3 个最可靠的特征描述 + 2 个优先改善方向；不展示过量密集数字。
2. **四大支柱及摘要**：和谐度、头脸架构、二态性表达、皮相细节。每类先以文字和可测项概览展示，不凭空生产 0—10 分。
3. **结构化测量工作台**：切换分组（整体、三庭、眼、眉、鼻、口、颌、对称、侧脸等）；点击指标，在用户原照片上画线、角、比值和解释，支持隐藏图层 / 看原图；若无侧脸则可提示补充侧脸。
4. **从证据到建议**：每项测量按“测到了什么 → 这表示什么 → 如果想改变视觉效果可以怎么做”链接发型、妆容、眼镜、色彩、照片拍摄建议；推荐支持保存到行动计划。

参考竞品的“测量过程可见/可核查”交互品质，但采用 BeautyAI 自有的布局、组件、文案、配色和数据结构；不复制其图片、商标、独特动效或页面源码。

### 免费 / 付费边界（保持 D27、D33 思路）

- **免费**：关键几何指标约 10—20 项、结构摘要、脸型、三庭、部分眼眉比例、个性化基础建议和可见测量标注。
- **一次性付费完整护照**：全部可靠可测的明细指标、可互动指标叠层、更详尽的分析解释和决策依据、侧脸补充分析、Look Studio 照片级发型试看；不必所有付费才给有价值内容。
- **不承诺** 176 项全部可测，更不把 C 类指标包装成硬核精确结果。

## 5. 分阶段实施（最快可演示优先）

### P0：面部评测 V3A —— 可运行、可演示

- 冻结“指标定义注册表”，有 id、中文名、公式/取点、可测条件、来源/可信度。
- 先实施现有 landmarks 能支持的约 25—40 个正脸 A 类指标，其中至少包括公开可核实的适用项：眼间距测试、外眦倾斜、宽高比、颌宽、三庭比例、眼纵横比等。
- 提供完整、真实可交互的照片叠层；一项指标点击后，显示真实几何线和计算值、单位/精度，无法测量显示原因。
- 继续将关键指标引用到现有发型/眼镜/风格建议。
- fake 和真实 CV 均能走上传 → 测量 → 结果 → 建议关键路径；不动支付/试看链路。

### P1：面部评测 V3B —— 侧脸与细节

- 侧脸选填引入不同视角的人脸定位和姿态 QC；侧面 8—12 项核心几何角度优先（鼻唇角、E 线、颏唇角等），无照片则为空。
- 增加眉毛、鼻翼、唇峰等分割，扩展到更多 B 类指标；高难皮相项目仍只做定性描述。
- 增加跨视角一致性、不确定性与局部测量边界标记。

### P2：有数据后再做统计评价

- 用户确实想知道“我的面部有哪些明显优势/需要优先改善的观感”，可先输出 **不依赖人口百分位的描述性判断**；
- 如果要上吸引力分/分位，另立决策与经过验证的数据集，不要把任何“看起来客观”的 0—10 数字当真相。

## 6. 关键测量算法与展示示例

- 水平眼间距：`intercanthal / mean(left_eye_width, right_eye_width)`，无量纲，先姿态归一化。
- 眼角倾斜：`atan2(y_outer - y_inner, x_outer - x_inner)`，注意图像 y 轴向下、左右眼号与符号约定。
- 面部长宽：`distance(facial_height_endpoints)/distance(zygomatic_left,zygomatic_right)`，视角稍偏会改变结果；若真实发际点不可见，只能输出“可见/标志点面长比”，不得标为发际-颏长。
- 三庭：`upper/(upper+mid+lower)`, `mid/(...)`, `lower/(...)`；缺发际时不强行使中下两庭归一到 1 后叫作“三庭”。
- 镜像不对称：先估计脸中线/矫正 roll+投影，再用同源对应点之间的归一化残差；镜像距离不是百分制“美感值”。
- 侧面 E-line：通过鼻尖与软组织颏前点的直线到上/下唇突出点作有符号垂距；用户仅上传正脸时为空。
- 所有结果保留足够的有效数字供算法使用，但前端只展示匹配成像精度的有效位数（一般比例两位，角度整度或一位），不滥用毫米绝对值。

## 7. MVP 验收（只验关键路径）

1. 正脸清晰无大遮挡时产出 25—40 个真实计算的客观正脸测量；至少 8 项支持点按照片上的真实叠线说明。
2. 刘海遮挡上庭、侧脸缺失、虹膜不可见时对应数值显示“未测量/需补照片”，绝不自动补数字。
3. 测量值与 overlay 均来自同一组 landmarks；前端不自行发明数值；同样输入 deterministic。
4. 不影响 V2.1 现有四区域、免费/付费、Qwen 试看以及照片 24 小时销毁。
5. schema/prompt/样例/adapter 一次协调更新；fake 模式 e2e 关键路径跑通。随后可让真实用户测试，不做重复 audit。
